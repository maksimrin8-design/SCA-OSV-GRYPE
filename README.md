# SCA-OSV-GRYPE

Бенчмарк для сравнения **OSV-Scanner** и **Grype** на зависимостях реальных GitHub-проектов.

## Что находится в репозитории

- `projects/manifest.json` — 30 уникальных upstream GitHub-репозиториев, их экосистемы и назначение.
- `.github/workflows/scan.yml` — GitHub Actions workflow: сканирует каждый репозиторий обоими инструментами, сохраняет JSON-результаты, версии сканеров, перечень dependency-файлов и фактический upstream commit SHA.
- `ground-truth/expected-vulnerabilities.csv` — независимый эталонный набор. Для подсчёта метрик используются только записи со статусом `verified`.
- `scripts/compare_ground_truth.py` — сравнение найденных пар package/version/advisory с подтверждённым эталоном.

## Запуск

1. Откройте **Actions → SCA benchmark (OSV-Scanner vs Grype)**.
2. Нажмите **Run workflow**.
3. После выполнения скачайте артефакт `sca-benchmark-comparison`. Исходные JSON каждого проекта сохраняются отдельными артефактами `scan-Pxxx-...`.

Для checkout репозиториев используется публичный GitHub-доступ. Если выбранный upstream-репозиторий требует авторизации, workflow завершится ошибкой checkout; приватные токены в workflow не передаются.

## Состав и воспроизводимость

В manifest перечислено 30 разных GitHub-репозиториев. Для всех 30 проектов в manifest закреплён неизменяемый 40-символьный commit SHA. Workflow дополнительно сохраняет фактический SHA checkout в `commit.txt`, чтобы можно было проверить входные данные конкретного запуска.

## Эталон и корректная интерпретация метрик

**30 репозиториев — это корпус для сканирования, а не утверждение, что все 30 содержат уязвимые зависимости.** Наличие уязвимостей web-приложения (например, XSS/SQLi бизнес-логики) не является ground truth для SCA.

Сейчас подтверждён один тестовый случай:

- `coder/osv-test`, `minimist@0.0.8`, npm
- `GHSA-xvch-5gv4-984h` / `CVE-2021-44906` (оба идентификатора сопоставляются как aliases одного advisory)
- исходный lockfile: https://github.com/coder/osv-test/blob/18c46d1b2a0119ff94e910e0b305819b763a4e79/fixtures/vulnerable/package-lock.json
- advisory: https://github.com/advisories/GHSA-xvch-5gv4-984h

Остальные проекты — кандидаты на сканирование, их expected vulnerabilities пока не объявляются подтверждёнными. До независимой проверки конкретного lockfile и диапазона версий advisory нельзя добавлять уязвимость в CSV со статусом `verified`.

Скрипт считает recall только по подтверждённым строкам. Найденные сканерами, но отсутствующие в неполном эталоне записи выводятся как `unadjudicated_findings`, а не как false positives. Поэтому на текущем этапе нельзя использовать этот корпус для итогового сравнения precision или заявлять полноту эталона.

## Что нужно завершить перед итоговым исследованием

1. Зафиксировать commit SHA всех upstream-проектов в `projects/manifest.json`.
2. Проверить dependency manifests/lockfiles на каждом выбранном commit.
3. Сверить каждый expected package/version с официальным OSV/GHSA advisory и внести доказательства в CSV.
4. Добавить отрицательные контрольные проекты/версии без известных уязвимостей.
5. Повторить запуск с зафиксированными версиями OSV-Scanner, Grype и датой баз уязвимостей.

Такое разделение не позволяет принять отсутствие записи в неполном эталоне за отсутствие уязвимости.
